# DESIGN.md

Read this fully before any UI work. Follow it strictly. Do not edit this file
or the tokens in index.css unless explicitly asked.

## Product

AI mock-interview platform. The user uploads a resume and a job description,
then has an ADAPTIVE timed interview. The AI decides how many questions to ask:
it asks follow-ups when an answer is weak or vague, moves on when satisfied,
and ends when it has enough signal, the time limit is reached, or the max
question cap is hit. Each answer gets feedback. The session ends with a final
report on weak spots.

LIMITS: min 5 questions, max 15 questions, time limit 20 minutes.
The timer overrides everything. The LLM decides only between min and max,
and returns a structured field: { "enough_signal": boolean, "reason": string }.

## User

Job seekers, often students and early-career, mostly on phones, often anxious.

## Feel

Calm, sharp coach. Serious but encouraging. Not corporate, not gamified.

## Stack

React 19, Vite, Tailwind v4 (@theme tokens), shadcn-pattern primitives in
components/ui, Lucide icons, Framer Motion for functional transitions only.

## Rules

### System
1. Use only tokens defined in index.css. No raw hex values, no arbitrary
   spacing values.
2. Display font for headings and the interview question. Sans for UI.
   Mono for timer and scores. Never Inter.
3. One primary action per screen. The accent color appears once per screen.
4. Reuse components from components/ui. Do not create one-off buttons, inputs,
   or cards.
5. Every screen needs empty, loading, error, long-text, and mobile (360px)
   states.
6. Accessibility: WCAG AA contrast, visible focus states, keyboard navigation,
   44px minimum touch targets, labels on all inputs.
7. Motion only to explain a state change. Under 200ms. Honor
   prefers-reduced-motion.
8. Destructive actions use an overflow menu plus an undo toast. Never a bare
   trash icon.

### Interview experience
9. Interview and feedback screens use "room mode": no navbar, no clutter,
   calm background.
10. The interview length is dynamic. Never show "Question X of N", a total
    question count, or a percentage-complete bar.
11. Progress is shown by (a) time remaining and (b) topic coverage:
    Behavioral / Technical / Problem-solving, each marked not started,
    in progress, or covered.
12. Label follow-up questions "Follow-up" so the user understands why the AI
    is probing deeper.
13. When the interview ends, say why in one line ("You've covered enough
    ground" or "Time's up"). Never end abruptly.
14. Show each fact once (time, progress, score). No duplicate indicators.
15. Pause the timer while the user reads feedback.
16. The greeting and the question are separate elements. Style the question
    like an interviewer speaking, not like a page heading.
17. The answer box shows a gentle guide ("Aim for 60-90 seconds"), not a
    character counter.

### Feedback and scores
18. Speak to the user as "you", never "the candidate".
19. Scores always use the score-low / score-mid / score-high bands (under 50,
    50-74, 75+) plus a one-line meaning. A 0 and an 82 must never look alike.
20. Feedback includes sub-scores (Structure, Depth, Impact, Relevance) and a
    "Here's a stronger answer" section using the user's own project.
21. The feedback screen ends with a line previewing what comes next
    ("Next: a follow-up on how you made that trade-off").

### Setup and copy
22. Setup states the time limit and that questions adapt to your answers.
    It never promises a number of questions.
23. Resume upload shows a file chip (name, parsed status, character count)
    with a collapsed preview. Never dump raw resume text into the page.
24. Difficulty uses a segmented control, not a native select.
25. Copy is specific and human. Banned phrases: "Unlock", "Seamless",
    "Ace your", "Welcome back", "Fast. Secure. Powerful.", "Evaluation
    Complete".

## Banned visuals

Blue/purple gradients, glassmorphism, glowing blobs, emoji as icons,
identical card grids, stock illustrations, shadows on everything,
icon-title-sentence feature triplets, centered hero plus three feature cards
by default.

## Data bugs to fix first

- Interview titles must be the role (for example "Full Stack Developer"),
  never text parsed from the resume. This is also a privacy leak.
- Dates must be unambiguous ("24 Sep 2026"), not "9/24/2026".
- A completed interview with a 0 score needs an explanation, not just a number.
- Feedback prompt must address the user as "you".
- Evaluation response must include: sub-scores, a stronger-answer rewrite,
  and enough_signal plus reason.

## Workflow

1. State your design decisions in 5 lines before coding.
2. Build one screen only. Do not touch other screens.
3. After coding, review against every rule above and list anything still
   generic. If you find nothing, look again and list three.
4. Never invent social proof: no fake user counts, ratings, testimonials
    or company logos. Use only claims that are true today.
5. Signature: the "red pen". Accent-colored hand-drawn underlines and
    margin notes mark where the user can improve, on the landing page,
    feedback and report. Do not use the accent for anything else decorative.
